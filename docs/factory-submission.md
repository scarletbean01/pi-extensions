# Resuming management, submitting briefs, and recovering receipts (ticket 02)

## Commands and tools

- `/factory resume <factory-id>` (interactive Pi session with UI only; blocked in Bootstrap worker sessions): explicitly admits the active Pi session incarnation as the exclusive local manager for `<factory-id>`. Retrying `/factory resume <factory-id>` from the same live session incarnation is idempotent. Another session, a reloaded runtime (`/reload`), a switched/resumed/forked Pi session (`/new`, `/resume`, `/fork`, `/clone`), or a reopened transcript cannot inherit or replace an active or orphaned manager in this slice.
- `/factory submit <factory-id> [reference]` (interactive Pi session with UI only; blocked in Bootstrap worker sessions): exposes a stable submission reference (`sub-<uuid>` if omitted, or the supplied literal `[reference]`) before opening the editor and before writing, opens a plain-text editor, and durably records the brief without launching a run. Cancelling the editor records nothing.
- `/factory receipt <factory-id> <reference>` and `/factory inspect <factory-id>` (read-only, available without a UI and from any session): inspect factory state, observable FIFO queue order (without exposing private session metadata), and recover committed receipts.
- `factory_inspect` tool: read-only structured tool supporting `action: "list"`, `action: "inspect"`, and `action: "receipt"` (with `factory_id` and either `reference` or `input_id`). No mutating factory tool is exposed to models, and normal chat or model-supplied flags cannot admit work.

## Input rules and limits

- **Brief text:** required nonblank, well-formed UTF-8 plain text (lone UTF-16 surrogates are rejected) up to **16 KiB UTF-8 (16,384 bytes)** measured in UTF-8 bytes.
- **Exact text preservation:** multiline text, CRLF/CR/LF line endings, tabs, leading and trailing spaces/newlines, control characters, literal path/issue/paste-marker strings, and non-ASCII UTF-8 characters are preserved verbatim. Because Pi's stock TUI `Editor` normalizes CRLF/CR/tabs, filters controls, auto-prepends spaces before `/~.`, expands paste markers, and trims on `submitValue()`, `/factory submit` uses a TUI editor wrapper (`RawBriefEditor`) via `ctx.ui.custom()` when `ctx.mode === "tui"` that preserves bracketed-paste and submitted payloads verbatim while sanitizing control characters in rendered TUI rows; in RPC mode `ctx.ui.editor()` returns the client value verbatim. Mentions of files or issues inside a brief stay literal text and never alter the graph, checkout, or permissions.
- **Submission reference:** literal non-empty, well-formed UTF-8 token (max 256 UTF-8 bytes, no whitespace or control characters). References are compared byte-for-byte (`BINARY` collation, case-sensitive) without normalization or numeric coercion.
- **Queue capacity:** up to **32 queued inputs per factory** (counting `queued`, `blocked`, and `retryable` dispositions; only `"queued"` exists in this slice). Inputs above 32 are rejected without evicting accepted work.

## Atomic admission, conflicts, and recovery

- Each accepted submission is committed in one SQLite `BEGIN IMMEDIATE` transaction (`DELETE` journal mode, `synchronous=EXTRA`, SHA-256 record/brief digests) that checks manager authority inside the transaction, allocates the `input_id` and monotonic `queue_position`, and binds `reference`, exact `brief`, and the factory's stored `v1` definition version. A receipt is returned only after commit and carries `factory_id`, `input_id`, `reference`, `bound_version`, `disposition` (`"queued"`), `queue_position`, `brief`, `brief_bytes`, and `accepted_at` (with no `task_id` or `run_id`).
- **Retry precedence:** identical-reference checks run before the 32-entry capacity check. Retrying the same `(factory_id, reference)` with the exact same brief returns the original receipt and current disposition without consuming capacity or rebinding; reusing the same reference with a different brief is rejected as a conflict; submitting identical text under a new reference creates a distinct queued input.
- **Definite rejection vs uncertain commit:** validation, authority fencing, conflicts, and full-queue rejections fail before commit and leave the queue unchanged. Failures at or after `COMMIT` (such as a lost acknowledgement) report an explicit uncertain outcome naming the factory ID and submission reference so the operator can reconcile read-only via `/factory receipt <factory-id> <reference>` (or `factory_inspect`) or retry `/factory submit <factory-id> <reference>` with the same reference.
- **Schema v1 compatibility:** SQLite schema v2 adds `factory_managers` and `factory_inputs` alongside `factories`. Read-only `list`, `inspect`, and `receipt` queries (`PRAGMA query_only = ON`) continue reading schema-v1 databases without mutating or upgrading them; schema-v1 databases upgrade cleanly inside `BEGIN IMMEDIATE` when written. Process-kill (`SIGKILL`) tests exercise SQLite transaction rollback and post-commit survival across process crashes, which does not by itself prove physical power-loss durability if local storage hardware or filesystems do not honor `fsync`/barriers.
